# Business Rules Enforcement Matrix & Test Verification

This document specifies the authoritative business rules governing the Research Project, Publication & Grant Management System (RPGMS), their specific database-level enforcement mechanisms, and their corresponding automated test implementations.

---

## 1. Authoritative Business Rules Matrix

| Rule ID | Business Rule Description | Database Enforcement Mechanism | Application Layer Handling | Automated Test ID |
|---|---|---|---|---|
| **BR-01** | Project `end_date` must be strictly after `start_date`. | Native CHECK constraint: `CONSTRAINT chk_proj_dates CHECK (end_date > start_date)` on `project`. | Form validation in `validators.py`; friendly error mapped in `errors.py`. | `test_br01_project_dates` |
| **BR-02** | Grant dates must satisfy `grant_end > grant_start` and `grant_start >= sanction_date`; changing grant dates cannot strand existing expenditures. | Native CHECK constraint `chk_gr_dates` on `grant_award` + `BEFORE UPDATE` trigger `trg_grant_award_bu` verifying `MIN(expense_date)` and `MAX(expense_date)`. | Wizard step validation; `errors.py` mapping. | `test_br02_grant_dates` |
| **BR-03** | Grant period must fall entirely within the parent project's lifetime (`start_date` to `end_date`); changing project dates cannot strand grants. | Triggers `trg_grant_award_bi`, `trg_grant_award_bu` on `grant_award` and `trg_project_bu` on `project`. | Date picker `min`/`max` dynamic bounds; friendly error mapped in `errors.py`. | `test_br03_grant_project_dates` |
| **BR-04** | Milestone due and completion dates must fall within the project's lifetime; changing project dates cannot strand milestones. | Triggers `trg_milestone_bi`, `trg_milestone_bu` on `milestone` and `trg_project_bu` on `project`. | Date input constrained by project dates; inline error display. | `test_br04_milestone_dates` |
| **BR-05** | Grant amounts, budget allocations, and expenditure amounts must be strictly greater than zero. | Native CHECK constraints: `chk_gr_amount` on `grant_award`, `chk_alloc_amount` on `grant_budget_allocation`, and `chk_exp_amount` on `expenditure`. | Positive decimal validation in `validators.py`. | `test_br05_positive_amounts` |
| **BR-06** | Sum of expenditures for any grant+head cannot exceed that head's allocation; sum of all expenditures cannot exceed total grant amount. | Stored procedure `sp_record_expenditure` with row locks (`SELECT ... FOR UPDATE` under `READ COMMITTED`), fresh aggregate reads, and atomic insertion. Direct runtime DML denied. | Live budget position widget in `expenditure/new`; server alert on rejection. | `test_br06_budget_caps` |
| **BR-07** | An expenditure's `expense_date` must fall within the grant's active period (`grant_start` to `grant_end`). | Triggers `trg_expenditure_bi`, `trg_expenditure_bu` on `expenditure` + procedure check in `sp_record_expenditure`. | Date input constrained to grant dates in UI. | `test_br07_expense_date` |
| **BR-08** | Publication DOI must be unique across the system when present and adhere to the standard DOI regex format (`^10\.[0-9]{4,9}/.+$`). | `UNIQUE KEY` on `publication.doi` + native CHECK constraint `chk_pub_doi`. | Client-side `/api/doi-exists` check; inline duplicate warning. | `test_br08_doi_uniqueness` |
| **BR-09** | Sum of allocations for a grant cannot exceed `grant_amount`; grant amount cannot be reduced below existing allocations or spending. | Transaction-owning procedure `sp_add_grant_with_budget` + `BEFORE UPDATE` trigger `trg_grant_award_bu`. | Live unallocated budget calculation in grant wizard step 2. | `test_br09_allocation_caps` |
| **BR-10** | Every project must have exactly one Principal Investigator (PI); PI transfer is atomic; PI cannot be removed/demoted via generic actions. | Generated column `pi_flag` (`1` if role='PI' else `NULL`) + `UNIQUE (project_id, pi_flag)`; triggers `trg_project_investigator_bu/bd` guard against demotion without `@rpgms_pi_transfer`; atomic `sp_change_project_pi`. | UI hides remove/demote buttons for current PI; dedicated Change PI modal. | `test_br10_single_pi` |
| **BR-11** | Combined effort across Proposed and Active projects for any researcher cannot exceed 100%. | Stored procedures `sp_register_project`, `sp_assign_investigator`, `sp_change_project_pi`, and `sp_update_project_status` lock researcher rows in ascending ID order and evaluate effort sum. | Dynamic workload bar and live API check `/api/researchers/<id>/workload`. | `test_br11_workload_limit` |
| **BR-12** | Only active researchers (`is_active = TRUE`) may be assigned to projects. | Validated in procedures (`sp_register_project`, `sp_assign_investigator`) + defensive triggers `trg_project_investigator_bi/bu`. | Inactive researchers greyed out in typeaheads; client-side disabled. | `test_br12_active_researchers` |
| **BR-13** | A milestone has status `Completed` if and only if `completed_date` is populated; non-completed statuses must have `completed_date IS NULL`. | Native CHECK constraint: `CONSTRAINT chk_ms_completion CHECK ((status = 'Completed' AND completed_date IS NOT NULL) OR (status <> 'Completed' AND completed_date IS NULL))`. | Milestone completion modal requires date; clears date on reversion. | `test_br13_milestone_completion` |
| **BR-14** | A Granted patent must have both `patent_number` and `grant_date` populated; `grant_date` cannot be before `filing_date`. | Native CHECK constraints: `chk_pat_dates` and `chk_pat_status` on `patent`. | Patent status select reveals required number and date inputs when set to Granted. | `test_br14_patent_status` |
| **BR-15** | Expenditure can only be recorded against a budget head that was formally allocated to that specific grant. | Composite foreign key: `CONSTRAINT fk_exp_alloc FOREIGN KEY (grant_id, head_id) REFERENCES grant_budget_allocation(grant_id, head_id)`. | Budget head dropdown populated dynamically from `/api/grants/<id>/heads`. | `test_br15_allocated_head_only` |
| **BR-16** | Publication date cannot be earlier than the start date of any project linked to it. | Triggers `trg_project_publication_bi/bu`, `trg_publication_bu`, and `trg_project_bu`. | Date comparison on linking; inline warning in publication form. | `test_br16_publication_dates` |
| **BR-17** | Completed or Cancelled projects cannot receive new expenditures, milestones, or team assignments. | Triggers on `expenditure`, `milestone`, `grant_award`, and `project_investigator` checking project status. | Action buttons hidden on closed project detail tabs. | `test_br17_closed_project_rules` |
| **BR-18** | A researcher can appear only once per publication; author order numbers must be positive and unique per publication. | Composite `PRIMARY KEY (publication_id, researcher_id)` and `UNIQUE KEY uq_author_order (publication_id, author_order)`. | Author repeater component with automatic re-ordering and duplicate checks. | `test_br18_author_order_unique` |
